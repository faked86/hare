# HareMQ (Lightweight Custom Message Broker)

HareMQ — это легковесный, высокопроизводительный асинхронный брокер сообщений класса Pub/Sub, написанный на чистом Go с нуля, без использования сторонних фреймворков и библиотек.
Проект спроектирован как аналог мини-Kafka/RabbitMQ для изучения системных примитивов, сетевого взаимодействия (TCP), ручного управления памятью, бинарной сериализации и многопоточности (Concurrency) в Go.

------------------------------

## 🏗 Архитектура и дизайн-решения
Проект разделен на изолированные слои в соответствии с современными практиками Go-разработки (cmd/ и pkg/):

   1. Сетевой слой (Transport): Базируется на стандартном пакете net. Реализует отказоустойчивый асинхронный TCP-сервер, обрабатывающий каждого клиента в изолированной горутине.
   2. Протокол передачи (Wire Protocol): Кастомный бинарный потоковый протокол типа Length-encoded. Решает проблему фрейминга (склеивания и разбиения пакетов в TCP-потоке) с помощью детерминированного чтения фиксированных заголовков через io.ReadFull.
   3. Хранилище в памяти (In-Memory Engine): Потокобезопасный движок управления топиками. Конкурентный доступ к структурам данных защищен с помощью дифференцированных блокировок чтения-записи (sync.RWMutex), обеспечивая максимальную пропускную способность для читателей.
   4. Система подписок (Pub/Sub): Построена на базе нативных буферизированных каналов Go. Потоки чтения (Reader) и записи (Writer) сокетов разделены на независимые горутины, что позволяет клиентам отправлять и получать команды параллельно в рамках одного TCP-соединения.

------------------------------

## 💾 Спецификация Wire-протокола
Брокер общается с клиентами с помощью бинарных пакетов. Структура пакета состоит из двух частей: Header (Фиксированные 5 байт) и Payload (Динамический размер).
## Структура пакета:

```
+--------------+-----------------+-------------------+-------------------+------------------+
| Command (1B) | Full Length(4B) | Topic Length (2B) | Topic Name (VarB) |    Body (VarB)   |
+--------------+-----------------+-------------------+-------------------+------------------+
| <----------- HEADER ---------> | <----------------------- PAYLOAD ----------------------> |
```

* Command (1 байт): Тип операции. 1 — PUBLISH, 2 — SUBSCRIBE.
* Full Length (4 байта, uint32, BigEndian): Общий размер оставшейся полезной нагрузки (Payload).
* Topic Length (2 байта, uint16, BigEndian): Размер строки с названием топика.
* Topic Name (Переменная длина): Название топика в байтах.
* Body (Переменная длина): Полезная нагрузка сообщения (передается только в команде PUBLISH).

------------------------------

## 🛠 Устойчивость к сбоям и управление ресурсами

* Защита от утечек дескрипторов: Жизненный цикл сокетов жестко контролируется через механизм defer conn.Close().
* Паттерн Dropping Slow Consumer: Для предотвращения каскадных блокировок всего брокера (Deadlock), отправка сообщений подписчикам обернута в неблокирующий select с веткой default. Медленные клиенты с переполненными буферами автоматически пропускаются, не заставляя продюсеров ждать под мьютексом.
* Корректная отписка (Cleanup): При падении или штатном отключении подписчика, Writer-горутина гарантированно вычищает его канал из памяти движка через метод Unsubscribe, исключая утечки оперативной памяти.

## Структура проекта

```
.
├── cmd
│   ├── consumer    # Скрипт подписчика
│   │   └── main.go
│   ├── producer    # Скрипт издателя
│   │   └── main.go
│   └── server      # Точка входа для запуска брокера
│       └── main.go
├── go.mod
└── pkg
    ├── server
    │   ├── engine  # Движок хранения и Pub/Sub
    │   │   └── engine.go
    │   ├── handler.go
    │   └── server.go
    └── transport   # Маршалинг и бинарный протокол
        └── transport.go
```

## Запуск системы (в трех разных терминалах)

   1. Запуск сервера брокера:
   
   go run cmd/server/main.go
   
   2. Запуск подписчика (Consumer):
   
   go run cmd/consumer/main.go
   
   Консьюмер подключится к брокеру, создаст подписку на топик metrics и перейдет в режим ожидания сообщений.
   3. Отправка сообщения (Producer):
   
   go run cmd/producer/main.go
   
   Продюсер отправит тестовый пакет в топик metrics и завершит работу. Консьюмер мгновенно отобразит полученное сообщение.
